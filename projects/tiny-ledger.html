账本不出门。

一个单人手机记账应用：界面只有一份源，Android 与桌面共用；没有任何网络代码，账本只写在本机上。这是五个自建仓库里产品完整度最高的一个。

功能范围 FOUR PAGES

记账、流水、统计、预算，
四个页面。

面向单个用户的手机记账。装机时是空账本，示例数据可在引导时选装。功能围绕日常录入与月度回看展开。

页面承担什么使用要点
记账 Entry 收支录入 跨类别滑动选分类、数字键盘直录，长金额自适应字号，单手也能记。
流水 Search 历史与检索 按月组浏览历史流水；关键词与金额双路搜索，可同时按文字和数额筛。
统计 Stats 月度回看 分类环形、30 日趋势、日历热力，加上月度体检与同环比对照。
预算 Budget 额度与建议 剩余额度与每日可用金额，给出健康分与调整建议。
III. 为什么 / WHY  ·  先划清数据的地界 003 / 008

它先回答不做什么。

记账工具常见的麻烦不在功能少，而在数据要交给谁。tiny-ledger 把这三件事挡在门外。

01

不强制注册账号

主流记账 App 往往要先注册账号。这里没有账号、没有同步、没有远端配置——装上就能记。

02

不把数据交给云端

账本只写在本机，代码里没有一行联网请求，也就谈不上把消费记录拿去做画像。

03

不让误删无从挽回

回收站保留 30 天，配合自动备份与损坏自愈，删错了或文件坏了都有退路。

本地优先不是少做功能，
是把数据的地界画清楚。

IV. 怎么用 / HOW TO USE•四步上手 004 / 008
日常路径 INSTALL → GUIDE → DAILY → BACKUP

从装到日常，
四步。

面向使用者的流程。开发侧只补一句：本地预览与提交前闸门都在仓库内跑，页面不提供可点的仓库链接。

01

装到手机 →

以 APK 侧载安装；覆盖安装需要和已装版本用同一证书。

02

首次引导 →

默认从空账本开始，示例数据在引导里可选装，用来熟悉界面。

03

日常四页 →

记账 → 流水 → 统计 → 我的。录入走记账，回看走流水与统计。

04

备份与迁移

可导出 JSON 备份恢复，或导出 CSV/XLSX；导入前自动备份，写失败全量回滚。

开发侧

浏览器预览跑在本地 127.0.0.1:8933；提交前过闸门 npm --prefix app run check。仓库在 GitHub 上是私有的，所以这里不放指向它的链接——放了访客也点不开。

设计核心 ONE SOURCE · SAME SEMANTICS · FIVE SKINS

一份界面源，
跨两端落地。

它真正想验证的是一件事：同一套 HTML/JS，能不能既做 Android 界面、又做桌面界面，而且数据安全语义在两端完全一致。

其一 / UI 真源

一份 UI 真源

Single Source
  • app/renderer/index.html 装结构、内联逻辑与基础样式。
  • styles/ 分片按 build-css.js 的注册顺序组装。
  • sync:assets 把成品逐字节同步进 Android 工程。
界面改一处两端同步
其二 / 存储一致

存储语义一致

Same Storage Rules
  • Android 的 StoreFiles.kt 与桌面的 storage.js 共享同一套约定。
  • 原子写、.bak、损坏自愈、备份轮换，两端都按同一规则走。
  • 渲染层 IO 适配 Android bridge / Electron IPC / localStorage 三种宿主。
换宿主语义不变
其三 / 皮肤

五套皮肤一档不落

Five Skins
  • Swiss Grid（terminal / terminal-dark）、Minimal Lines（ink / paper）、Geometric Bauhaus（bauhaus / bauhaus-dark）浅深两档都有。
  • Pixel 只提供深色，Mist Blue 只提供浅色，缺的那一档不做硬凑。
  • 用 ◐ 在档间切换，并记住上次选择。
切档记忆偏好
五条防线 BACKUP · EXPORT · GUARD · TRASH · HEAL

账本在本地，
更要守得住。

数据不出机器，意味着没有云端那份兜底。下面五条，是把"只存本机"这件事做扎实的部分。

  • 01
    自动备份

    私有目录保留最近 3 份日快照；Downloads 目录会尝试再放 3 份。

  • 02
    手动导出

    可导出 JSON 备份用于恢复，或导出 CSV / XLSX 用于外部查看。

  • 03
    导入守卫

    导入前校验格式、自动备份当前数据；一旦写入失败，全量回滚。

  • 04
    回收站

    删除的记录在回收站保留 30 天，可恢复，也可到期彻底清除。

  • 05
    损坏自愈

    发现账本文件损坏时先保留原文件，再从最新备份恢复。

VII. 验证与文档 / VERIFY•怎么证明它没坏 007 / 008
质量口径 GATES & DOCS

改动之前先过闸门，
留痕交给文档。

一个 UI 跨两端的项目，靠手点回归撑不住。质量分两栏：一栏是可重复跑的闸门，一栏是写给下一个自己的文档。

闸门 / CHECKS

能自动跑的，都自动化

  • +check 无依赖闸门：派生资源同步、逐脚本语法检查、存储/数据/动画性能回归
  • +Electron 套件：数据语义、皮肤与布局矩阵、降级动效、持久化回滚、故障注入、端到端
  • +真机回归：在 Android 设备上把主路径再走一遍
文档 / DOCS

做过的决定，写下原因

  • +docs 00–10 编号文档：索引、架构、构建与测试、路线与决策、交接、功能清单、测试索引、安卓存储桥
  • +CHANGELOG：每个版本改了什么，按时间排开
  • +archive：归档旧文档，索引仍能找到去处

只有 Android 正式发版，
源码锁在私有仓库。

目前只有 Android 8.0+ 正式发版，iOS 还没开工。仓库就在 GitHub 上，但设成了私有：源码访客读不到，APK 只挂在私有仓库的 Releases 页（README 上的版本徽章和「APK on the Releases page」指的都是那一处）。点不开不等于不存在——只是这一页没有访客能按的下载按钮。
