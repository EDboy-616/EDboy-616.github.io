是什么

一句触发词，一份能核的日报。

对装了它的 AI agent 说「金融日报」，它自己去采公开行情、检索权威媒体要闻，产出一份报刊风日报：HTML 必交，宿主有渲染能力时再附 3x 高清长图。

它由两部分组成：一份给 agent 读的 SKILL.md，和一组取数脚本。SKILL.md 把流程写死——取数、复核、排版、按宿主能力交付；scripts/fetch_public.py 负责硬行情，只用 Python 标准库，不需要 API Key，也不接付费数据源。

版面固定为 13 个板块：价格速览条、头版、宏观与政策、国际与央行、汇率、行业扫描、资金流向、机构观点、今日关注、数据说明、页脚等。板块固定不是为了好看，是为了让今天的日报能跟昨天的日报逐栏对齐——版式一变，比较就失效了。

  • 01
    一个 Agent Skill

    遵循 agentskills.io 开放规范。SKILL.md 是唯一事实源，各宿主的适配文件由 build_adapters.py 从它生成，不手改生成物。

  • 02
    零 API Key

    行情走公开接口：新浪报价、美国财政部 CSV、CNBC 公开价。渲染 3x 长图才另需 playwright、pillow 与 chromium；缺依赖就只交 HTML，不擅自装包。

  • 03
    15 个安装目标

    14 个可由脚本安装——Claude Code、Codex CLI、Copilot、Gemini CLI、Qwen Code、Cursor 等；第 15 个是纯对话宿主（GPTs、Kimi、豆包一类），只能粘贴系统提示词。

  • 04
    两种跨宿主机制

    注入式把适配器正文写进宿主常驻的上下文文件，说触发词就跑；目录式把 skill 复制进宿主的 skills 目录，按需加载更省上下文，但多数宿主只认显式调用。

II. 三条铁律 / DATA RULES · 任何降级都不放宽 003 / 008

模型会把数字编得很像。

所以这个技能做的第一件事不是排版，是把每个数字的来源钉住。三条规则写在 SKILL.md 里，能力降到哪一档都不打折。

I

数字必须可溯源

每个数字要么来自脚本输出，要么有两个以上权威源一致。两个源对不上，就写明「X 源报 A，Y 源报 B（待核）」。

II

取不到必须留痕

撤下这个指标，或者标「待核」。禁止编造，也禁止把两个数取平均糊过去——含糊过去比空着更贵。

III

读者要能核账

页面底部的「数据说明」板块必填，披露每个数字的来源。它写进 HTML，不是聊天里的一句口头保证。

一份日报的可信度，不取决于写得多顺，取决于能不能被核。

怎么用

装进去，说一句，等产出。

四步里贴的命令都抄自仓库 README，参数没改过；第 2 步那行是宿主对话里要说的话。

01

装 Skill →

先用 install.py --list 看 15 个落点，再挑一个装进当前项目，或者装到个人级目录。

python scripts/install.py --target claude
02

说触发词 →

注入式宿主里说这四个字就自动跑完整流程；走原生 skills 目录的宿主需要显式调用，或者用 gh skill install。

金融日报   # 对装了它的 agent 说
03

等产出 →

能跑命令就有 HTML，装了 Playwright 就多一张 3x 长图。缺什么降什么档，并在页面里注明。

outputs/market_news_20261112.html  # 网页必交
04

核来源

产出同时落一份结构化 JSON，每个字段带 src 与 status。对某个数字有疑问，先看这里；想单独验数据源连通性就自己跑一遍脚本。

python scripts/fetch_public.py --date 2026-11-12 --out-dir ./raw

IV. 亮点 / WHAT HOLDS UP•三关 005 / 008
亮点三关

取数、体例、可移植。

这三关是这个仓库里我认为值得单独说的部分：任何一关松掉，产出的日报就没有价值。

GATE 01 / DATA

零依赖取数

STDLIB ONLY

  • fetch_public.py 只用标准库，不装包、不给 Key、不交钱。
  • 接口失败就跳过并记录状态，不硬凑一个数填上去。
  • 取数与写稿分开：脚本给数字，模型只做编排和文字。

脚本给数 取不到就撤下

GATE 02 / FORMAT

13 个固定板块

EDITORIAL LAYOUT

  • 板块名与顺序每天一样，可以逐栏比，不用重新认版式。
  • 红涨绿跌、暖纸墨蓝金线：排式是信息层级，不是装饰。
  • 「数据说明」是必填板块，写在版面里，删不掉。

体例固定 每天可比

GATE 03 / PORTABILITY

15 个宿主两种机制

INJECT / SKILLS

  • 同一份 SKILL.md 生成各宿主适配文件，改一处就全改。
  • 注入式常驻上下文换自动触发，目录式按需加载换省上下文。
  • 连提示词位置都紧张的最窄宿主，另备一份精简版系统提示词。

装不上就粘贴 铁律不降

边界

它只到初稿为止。

这份日报是给你省时间的整理稿，不是决策指令。写清不做什么，比吹能做什么更有用。

DO / 做

它负责这些

  • +只用公开数据源，脚本直连，不装连接器。
  • +每个数字带来源，页脚「数据说明」统一披露。
  • +取不到就撤下或标「待核」，不留空白也不编。
  • +宿主能力不够就降档，并写明这一版少了哪一环。
DON'T / 不做

它不负责这些

  • —不做投资建议：仓库与产出都标注「仅供信息参考，不构成投资建议」。
  • —不接付费数据源与私有接口，也不代持任何账号。
  • —不保证实时：美国财政部收益率曲线是 T-1 发布，非交易日沿用最近交易日收盘。
  • —不假装全都测过：install.py 的宿主路径表来自官方文档与安装器交叉核对，README 写明未在本机逐一实测。
VI. 工程规范 / ENGINEERING•怎么保证它不烂掉 007 / 008
工程规范

改一处，闸门就响一声。

这个仓库会被别的 agent 接手，所以规矩写在 CI 里，不写在记忆里。

  • 01
    GitHub Actions 自检闸门

    .github/workflows/verify.yml 在 ubuntu 与 windows 双矩阵上跑：规范校验、适配层漂移检查、四个脚本 smoke、claude.ai 上传包打包。README 顶部的 CI 徽章就指向这个 workflow。

  • 02
    MIT 协议

    仓库根目录有 LICENSE，GitHub 上登记的许可证是 MIT。可以自用、可以改、可以拿去再做一份适配，只要保留版权声明。

  • 03
    HANDOFF.md 交接文档

    写给接手的 agent：项目状态、架构约定、验证方法、待办事项。README 开头一条 NOTE 直接指过去。

  • 04
    README 自带产出预览与方案对比

    三张预览图（报头与头版、板块细节、整版长图）、「常见做法 vs 本技能」四条对比表，外加一张数据源与复核矩阵：主源与复核源逐指标列出。
