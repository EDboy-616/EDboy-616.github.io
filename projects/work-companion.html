I · 是什么

把说出口的承诺，落到对话之外。

它不是待办软件，也不接管日程。它只做四件事，而且都在你说完之后才做。

本体是一段纯提示词：一份 SKILL.md，装进任何遵循 Agent Skills 规范的 agent 就能用。要解决的问题只有一个——你在这轮交代的事，下一轮就被上下文滚走了。它把那句话从对话里摘出来，落到一个固定位置：主目录下的 work-companion/commitments.md，不改名、不换位置。

清单不会写进你当前的项目目录，跨项目共用一份，在哪个仓库里干活读到的都是它。两台电脑不同步，各写各的——这是明确的取舍，不是还没做。

  • 01
    当场记下

    你亲口说出承诺、自己的任务，或明确要求盯着某个跟进时，才写进清单。只有这一轮真的写进去了，它才说「我记下了」。

  • 02
    相对日期当场换算

    11 月 16 日（周一）说「周五要交个方案」，落成 2026-11-20。有歧义就反问一次，只问一次，不猜。

  • 03
    被问就列全

    你问「我有什么没做的」，它分「你要做的」和「等对方」两列列完，段内按到期日排。作废的不列，删掉的连提都不提。

  • 04
    收尾时最多一句

    你说出明确的收尾词（「先这样」「收工」），而清单里有逾期或三天内到期的条目，它在回复末尾顺带提一句——一次只装一条。

II. 解决什么问题 / WHY  ·  三个反复出现的坑 003 / 007

说过的话，下一轮就没了。

不是模型笨，是上下文本来就会滚走。而多数提醒工具在补这一块时，顺手制造了新的噪音。

01

待办说在对话里

这一轮交代的事，滑过三屏就找不回来。要它活得比对话久，就得有个对话之外的地方存着。

02

提醒一多就变唠叨

催得越勤，人越会把它关掉。催促、施压、情绪安抚，从一开始就被排除在职责之外。

03

「定时回顾」听着很对

可没有一个可观察的信号能告诉模型「现在该回顾了」。硬做出来的定时小结，不是瞎猜就是空许诺。

没有可靠信号就不做定时回顾——砍掉的特性也要写进 README。

III. 怎么用 / HOW TO USE•四步，装完就开始用 004 / 007
怎么用

装进去，然后正常说话。

没有配置界面，没有快捷键，也没有账号要登。四步里只有第一步是新的。

01

装 →

一条 npx skills add，或跑仓库里的 install.sh / install.ps1，或在 Claude Code 里添加插件市场。

npx skills add EDboy-616/work-companion
02

正常说话 →

「周五之前把报告发给他」。它换算出日期、写进清单，并把清单路径告诉你一次。

03

随时问 →

「我有什么没做的」。要做的与等对方的分两列列全，段内按到期日排。

04

收尾

你说「先这样」。有到期项时它在回复末尾提一句；没有就什么都不说。

实现口径

主体是提示词工程：唯一真相源是一份 SKILL.md，正文里不出现任何工具名，也不依赖绝对路径与环境变量，所以换宿主不用改文案。仓库里的 Python（scripts/ledger.py）只是可选的清单脚本，负责查询、改期、去重这类机械活——不装照样完整工作，装了也不会多出一项能力。

IV. 亮点 / WHAT HOLDS UP•三条都能在仓库里查到 005 / 007
三关

最轻的一个项目，也最看得出取舍。

这一页没有性能数字可讲。能拿出来的是三条事实，你在仓库里都翻得到。

第一关 / NO INFRA

零基建

一份文件 / Prompt only
  • 一份 SKILL.md 就是全部核心：没有服务端、没有依赖安装、不联网、不收集数据。
  • 清单写在你自己的机器上；你说「忘了吧」即整条删除，不留备份、不复现。
  • 可选脚本用文件锁加原子替换写入：要么写全，要么不写，两个会话同时写不丢条目。
数据留在你的机器
第二关 / 19 TARGETS

19 个宿主

跨平台 / Portability
  • 遵循 Agent Skills 开放规范：一个目录加一份带 frontmatter 的 SKILL.md。
  • Claude Code、Codex、Cursor、Gemini CLI 等 19 个安装目标，三种装法任选。
  • 路径来自各宿主文档与 vercel-labs/skills 的支持列表；除 Claude Code 外本仓库没逐个实测。
本机实测过仅 Claude Code
第三关 / FINISH

产品化打磨

交付质量 / Craft
  • 中英双语 README，配亮／暗双主题横幅与一整套自建 SVG 徽章。
  • 有 CHANGELOG 与版本记录（当前 v0.5.0），另留了兼容性决策与试跑剧本。
  • README 里有一张「刻意不做什么」表：2026-11-12 砍掉的五个特性，逐条写明理由。

V · 职责边界

它只盯你自己答应的事。

一个工具把「我不做什么」写清楚，比多列三条功能更有用。下面是这张清单的两侧。

管 / IN SCOPE

你亲口说出的那部分

  • +你亲口说的承诺与自己的任务
  • +你明确要求盯的跟进，和等对方的条目
  • +相对日期换算成绝对日期，歧义当场问一次
  • +你问起时，两列列全，按到期日排
  • +你明确要求定时，它才挂提醒
不管 / OUT OF SCOPE

别人更擅长的，就不做

  • −不接管日历，不发外部通知
  • −不打断当前工作，不催、不施压
  • −不做优先级排序，只按到期日排
  • −不管项目与代码知识，那是记忆系统的事
  • −没写进清单，就不说「我记下了」
