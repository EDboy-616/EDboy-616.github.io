验证码只
在这台电脑里。

一个只跑在自己机器上的双重验证码保管库。第一次保存时设主口令，之后重启解锁即用——不建账号、不上云、断网也出码。工程强度最高的一版，只是仓库设成了私有，源码不对外可见。

公开状态

II. 是什么 / WHAT IT IS•Nº 02 · localotp 002 / 008
功能

一个离线的双重验证码保管库。

本机、离线、加密的 TOTP 保管库。第一次实际保存条目时设主口令，之后重启应用输主口令解锁即用。主界面是「大码双栏」：六位验证码、剩余秒数、复制操作在同一屏上，不用翻页找。

  • 01
    本地加密保管

    密钥条目全部以密文存在本机一个文件里，主口令只在解锁时进内存，用完即清。

  • 02
    大码出码

    支持 SHA1 / SHA256 / SHA512、6–8 位、自定义周期的 TOTP 出码，断网也能算。

  • 03
    导入与备份

    可导入 Aegis JSON、Google Authenticator 迁移链接，识别本地二维码图片，也能导出完整的 .lotp 快照。

  • 04
    桌面壳层

    托盘常驻、开机自启、全局热键呼出，失焦或隐藏窗口时自动上锁。

III. 解决什么问题 / WHY  ·  否决掉的东西，才说明它是什么 003 / 008

验证码这件事，不该经过任何人。

它要解决的不是「更方便」，而是把 2FA 从云端和手机里拿回来，只留在自己这台电脑上。为此它宁可放弃几样看起来很实用的功能。

一

不做账号、不同步、不上传

2FA 一上云，第三方就同时握有了你的账号和它的验证码，两道门变成一道。所以这里没有账号体系，没有同步通道，没有任何上传路径。

二

主口令明确不可恢复

「口令丢了想找回」在这个领域只有一条路——留后门。与其偷偷留，不如把「找不回」写在界面上，让你第一次就清楚代价。

三

桌面端断网也能出码

手机不在身边、没信号、没电就登不进去，是这个场景最卡人的一刻。桌面端离线算码，把这条依赖也切断。

安全工具的诚实，是把「找不回」这件事写在界面上。
日常使用

装上、加条目、设口令、解锁。

不联网、不注册。下面四步是普通用户的全部动作；技术侧的命令放在最后，只说明作者自己怎么把关，不引导你去 clone。

I.

装到本机→

Windows 上有三种产物：NSIS 安装器、中文 MSI、免安装 exe。三项都还没做代码签名（Authenticode 均为 NotSigned），所以下载后 Windows 会弹未知发布者提示；MSI 的覆盖升级靠固定的 UpgradeCode 与 allowDowngrades=false，装过旧版直接装新版即可。

II.

加条目→

点右上角的加号，填名称、账号、密钥；服务方给了恢复码就一起填进去。

III.

首次保存设主口令→

第一次真正保存时设主口令，设定后保管库以密文落盘在 %APPDATA%\dev.localotp.desktop\vault.lotp。

IV.

日常解锁

以后每次启动先输主口令解锁；窗口失焦或隐藏就自动上锁，界面回到等待解锁的状态。

作者自用的验证闸门 本地跑 pnpm check:env、pnpm verify、pnpm tauri build 三道检查后才出包——列举它们只为说明发布前把关流程，不是让访客去自行构建。
V. 亮点三关 / CRAFT•工程上真正较真的地方 005 / 008
为什么值得单独讲

加密、结构、对拍，三关都过。

这版最花力气的不是界面，而是它把「安全工具不能出错」这件事拆成三层约束，每一层都有对应的验证手段。

第一关 · 加密

加密不是贴上去的

Crypto at rest

  • AES-256-GCM 加密，密钥用 scrypt 派生，且 KDF 参数纳入 AAD。
  • 临时文件写入 + 原子发布 + .bak 轮换；首次建库独占创建、不覆盖已有文件。
  • 恢复码只随完整 .lotp 保存，不进日志、不进搜索、不随跨应用导出。
  • 复制出来的验证码默认 15 秒后被覆盖。

口令派生 → 落盘全程密文

第二关 · 结构

结构约束写死在代码里

Hard boundaries

  • src/core/*.ts 不 import 任何平台 API，时钟与随机数都从参数注入。
  • Rust 侧只吃不透明 JSON，格式权威在 core/schema.ts。
  • 格式变化必须向后兼容，遇到不支持的版本明确报错而不是猜。

核心层 ↔ 平台单向依赖

第三关 · 对拍

两套实现互相对拍

Cross-check

  • TypeScript 内存后端与 Rust 真文件后端跑同一套契约测试。
  • scripts/selftest.mjs 是独立第二套实现，对拍 RFC 6238 / 4226 公开测试向量。
  • tools/*.ps1 在真窗口里验首启、锁定、恢复码、托盘热键与发版验收。

两条实现同向量比对

跨端现状

Windows 能用，其余在编译层。

桌面端先做 Windows，其它平台目前只到「核心能编译通过」，还没有可交付的应用。

localotp · 平台推进状态（截至 v0.5.0）
平台状态推进到哪一步
Windows 主开发 桌面端完整：保管库、托盘、自启、热键、安装包都已就位，是当前唯一可日常使用的平台。
macOS 内核已验 核心与加密在 macOS 上验证通过，但还没有发布对应的应用产物。
Android 编译通过 仅 lotp-store、lotp-aegis 两个 crate 做了多 target 编译并成功，无 UI。
iOS 待工具链 同上仅到编译层，再往前需要 Apple 签名与真机工具链才能推进。
VII. 边界 / BOUNDARIES•做什么，不做什么 007 / 008
能力边界

写清楚它刻意不碰的东西。

很多「缺的功能」是有意的取舍。下面左列是当前支持的，右列是不在路线图上、或明确拒绝的。

支持 / In scope

这版做到

  • [✓]离线 TOTP 出码：SHA1 / SHA256 / SHA512，6–8 位，自定义周期
  • [✓]导入 Aegis JSON、Google Authenticator 迁移链接、本地二维码图片（PNG / JPG）
  • [✓]完整 .lotp 快照备份与恢复
  • [✓]托盘、开机自启、全局热键、失焦与隐藏即锁
  • [✓]AES-256-GCM + scrypt 加密，剪贴板默认 15 秒覆盖
不在路线图 / Out of scope

刻意不做

  • [×]不支持 HOTP / Steam 令牌，非标算法一律不做
  • [×]不做摄像头扫码，只读本地 PNG / JPG 图片
  • [×]无云同步、无账号、无遥测统计、无崩溃上报
  • [×]无「忘记口令找回」——主口令无法找回，恢复码不能解密主库
